## 修复：帖子详情页导航高亮错误（分区前缀路由方案）

### 问题根因
详情页路由是共享的 `/forum/topic/:id`，`MainLayout` 的导航高亮用 `pathname.startsWith(item.key)` 匹配，所以任何详情页 URL（如文章帖 `/forum/topic/123`）都命中 `/forum` → 顶部和左侧导航永远高亮「论坛」。

### 方案：分区前缀路由 + 详情页自纠偏
把详情路由按分区拆成四个，都指向同一个 `TopicDetail` 组件：
- `/forum/topic/:id`（保留）
- `/qa/topic/:id`（新增）
- `/articles/topic/:id`（新增）
- `/resources/topic/:id`（新增）

`MainLayout` 的 `selectedKey` **无需改动**——分区前缀 `/forum`/`/qa`/`/articles`/`/resources` 本就是菜单 key，`startsWith` 会自然匹配到正确分区。

### 关键设计点：自纠偏重定向（解决「源对象拿不到分区」和旧书签）
`Profile.tsx` 的「我的回复」tab 从 `getUserPosts` 只拿到 `topic_id`，没有 `type`（后端 `list_user_posts` 不返回 type）；旧书签也走 `/forum/topic/:id`。对这些场景：
- 初始导航仍走 `/forum/topic/:id`（fallback）
- `TopicDetail` 拿到 `topic.type` 后，若当前 URL 的分区前缀与 `topic.type` 不符，则 `navigate(正确路径, { replace: true })` 自动纠偏。纠偏后 URL 前缀匹配，导航高亮即正确，且 replace 不污染历史。纠偏目标前缀已匹配，不会循环。

### 改动文件（6 个，纯前端，无后端改动）

**1. `src/utils/constants.ts`** — 新增详情路径构造 helper：
```ts
export function topicDetailPath(type?: TopicTypeKey, id: number | string): string {
  const base = type && TOPIC_TYPE_META[type] ? TOPIC_TYPE_META[type].route : '/forum'
  return `${base}/topic/${id}`
}
```

**2. `src/router/index.tsx`** — 新增三条分区路由（指向同一 `<TopicDetail />`）：
```tsx
{ path: 'forum/topic/:id', element: <LazyPage><TopicDetail /></LazyPage> },
{ path: 'qa/topic/:id', element: <LazyPage><TopicDetail /></LazyPage> },
{ path: 'articles/topic/:id', element: <LazyPage><TopicDetail /></LazyPage> },
{ path: 'resources/topic/:id', element: <LazyPage><TopicDetail /></LazyPage> },
```

**3. `src/pages/Forum/TopicDetail.tsx`** — 加自纠偏重定向 + 顺手修标签跳转：
- 引入 `useLocation`，拿到 topic 后比对 `TOPIC_TYPE_META[topic.type].route` 与当前 pathname 前缀，不符则 `navigate(topicDetailPath(topic.type, topicId), { replace: true })`。
- 标签点击 `navigate(`/forum?tag=...`)` → `navigate(`${meta.route}?tag=...`)`（让标签回到本分区，而非永远跳论坛；列表页暂不读 query 参数是既有现状，不在本次范围）。

**4. `src/pages/Home.tsx`** — 热门话题点击改用 `topicDetailPath(topic.type, topic.id)`。

**5. 四个列表页**（`Forum/List.tsx`、`QA/List.tsx`、`Article/List.tsx`、`Resource/List.tsx`）+ `Resource/List.tsx` 的「查看详情」按钮 — 改用 `topicDetailPath(item.type, item.id)`（列表项 `TopicListItem` 本就有 `type`，统一用 item.type 而非硬编码分区）。

**6. `src/pages/User/Profile.tsx`**：
- 「我的话题/问答/文章」tab：`topicDetailPath(item.type, item.id)`（item 有 type）
- 「我的回复」tab：`topicDetailPath(undefined, item.topic_id)`（无 type，走 fallback，详情页自纠偏）

### 不改动 / 已正确
- `MainLayout.tsx` selectedKey —— 分区前缀已匹配菜单 key，无需改。
- `TopicDetail` 删除后跳转 —— 已用 `TOPIC_TYPE_META[topic.type].route`，分区正确。
- `TopicCreate` 创建/编辑后跳转 —— 已用 `listPathMap` 跳本分区列表，不在本次范围。
- `navigate(-1)` 返回按钮 —— 走浏览器历史，无需改。
